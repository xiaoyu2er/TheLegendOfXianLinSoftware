# 假货必须登记在册，配双向检查

M2 要做到打完仗能走回地图，而结算要发物品、发钱、加经验——背包、装备包、
钱包属于 M3 与 M4，现在都不存在。**M2 用假的顶上**，但每一样假货都要登记在
一份清单里，写明它归哪张票，并配一个**两个方向都会红**的检查：清单说它是假的
而代码已经是真的，红；代码还是假的而清单里删了它，也红。

理由不是假货本身有问题，是**一个被忘掉的假货和一个正常工作的真货长得一样**。
M3 做出真背包的那天没人会记得战斗这边还挂着一个假的，于是两套并存，而两套
并存的样子和一套正常工作的样子完全相同。

## Considered Options

- **让假货在被调用时打警告**。「没人看警告」和「没有警告」长得一样。
- **只写进票面注释**。靠人记，正是这个项目反复吃亏的形状。

## Consequences

双向对撞这个机制在这个仓库已经跑通过一次——`implemented.ts` 与
`expected.ts` 就是这么对的（哪些剧本能比对 vs 哪些剧本声称能比对）。这里照抄
它的形状，不发明新的。
