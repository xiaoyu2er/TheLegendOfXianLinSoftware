# 战斗里的三个菜单画进画布，不用 React

`docs/MIGRATION-PLAN.md` 定的分工是「Pixi 画场景与战斗，React 画 UI（菜单 /
商店 / 装备 / 技能 / 对话框）」。战斗里的指令菜单、技能菜单、药品菜单正好卡在
这条线上——它们是菜单，但长在战斗里。**这三个走 Pixi，是对那条分工的
有意偏离。**

理由是判据：这三个菜单在原版里画的是**按钮贴图**，不是文字排版，而战斗要
逐像素比对。贴同一张图天然一致；用 React 加 CSS 重做，要做到每个像素相等
几乎不可能。

## Considered Options

**React 画，靠截图仍能截到它**。取图走的是 `Page.captureScreenshot` 裁
1024×640，截的是页面合成后的画面，所以 DOM 元素**确实会**被截进去——这条
路技术上通。否掉它的是像素相等这个要求，不是截不截得到。

## Consequences

**M3 的独立菜单系统同样走全 Pixi 贴图，不用 React DOM。**（决定本身在
`xl-6lo.2` 里定，这里只把它接到本 ADR 的判据上。）

- **天书页那批按钮与战斗菜单是同一种东西。** 它们全部经 `MenuButton.drawButton()`
  的 `g.drawImage` 出画，一颗按钮就是「常态 / 悬停 / 按下」三张 png：
  `src/menu/FuncButtons.java` 里 **42 条 `new ImageIcon` 路径**、零 `drawString`；
  `sources/菜单/天书/` 下 **50 个文件** = 16 颗按钮 × 三态（48）+
  `主人公4人2.png` + 背景 `天书.png`。上面那条「贴图天然一致，CSS 重做几乎
  不可能像素相等」原样适用，一个字都不用改。

  （**别拿「`drawString` 是 0」单独当判据**：`FuncButtons` 是个只造
  `MenuButton` 的工厂，它的 `drawImage` **也是 0**，那个数谁都不区分。）

- **真正属于文字排版的是五块，不是三块。** 分母从源头数，别抄这份名单 ——
  `src/menu/` 下 `drawString` 落在哪几个文件，跑一遍就有（GBK 源码要先转码）：

  ```bash
  for f in src/menu/*.java; do
    n=$(iconv -f GBK -t UTF-8 "$f" | grep -c drawString)
    if [ "$n" -gt 0 ]; then echo "$n $(basename "$f")"; fi
  done
  ```

  （写成 `if` 不是讲究：`[ "$n" -gt 0 ] && echo …` 会让循环以最后一个文件的
  真假收尾，而 `src/menu/` 的最后一个恰好是 0，整条命令退出码 **1** —— 数对了
  却像失败了。）

  2026-09-08 在本分支上跑出五个（**读数，不是规格**）：`EquipPanel` 16
  （属性数值 + 装备名）、`DrugPanel` 7（药品名）、`MagicAnimation` 2
  （技能说明）、`Command` 1（`"当前任务:"` 标题栏）、`Scoll` 1（人物等级，
  红色 `文鼎粗钢笔行楷` 30pt）。**后两块是 xl-6lo.2 的「只有三块」漏掉的**，
  而 `Scoll` 那块尤其要当心：它指名一款浏览器多半没有的中文字体，正是
  `web/src/compare/expected.ts` 开头讲的「最会抖的东西是后备字体」。

  这些缺口不靠「换个渲染载体」消掉，靠 `expected.ts` 的 **`gaps` 分区表态** ——
  圈出矩形、写量出来的 `maxPixels`，缺口补上了那张表也要跟着红。

否掉的是**混合**（贴图走 Pixi、文字层叠 DOM）：两套坐标系、两套字体，文字的
像素缺口一个都没少，却多了一层同步成本。
